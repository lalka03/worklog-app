# Worklog — тестовая серверная часть

Функция использует временный IAM-токен привязанного сервисного аккаунта. Постоянные S3-ключи, секреты в репозитории и изменения Android-приложения не требуются. Firebase и локальное хранение остаются неизменными.

## Развёртывание в Yandex Cloud

1. Каталог `worklog` → Cloud Functions → создать функцию `worklog-api`. Не включать публичный вызов.
2. Создать версию на Python 3.14 (или 3.12, если доступна), скопировать `index.py` в файл `index.py` в редакторе.
3. Точка входа `index.handler`, память 128 МБ, таймаут 15 секунд, сервисный аккаунт `worklog-storage`.
4. Сохранить версию. Оставить функцию закрытой, переменные окружения не нужны для пробы.
5. На вкладке тестирования вызвать с JSON `{"action":"probe"}`. Ожидается HTTP 200 с `ok: true`. В бакете появится `_diagnostics/probe.json` без личных данных.

Роль `storage.uploader` на конкретный бакет позволяет записать и прочитать объект. Расширять права на весь каталог не нужно.

## Резервные копии (пока отключены)

Закрытая функция поддерживает действия `save` (поле `backup` с `settings`, `days`, `version: 1`) и `load` (поле `backupId`, возвращённое при сохранении). Каждая копия имеет новый ID; удаление не поддерживается. Для тестов администратором в заведомо закрытой функции эти действия можно включить переменной `WORKLOG_BACKUPS_ENABLED=1`. Для доступа из APK нужна отдельная проверка личности и прав пользователя, прежде чем делать интерфейс доступным в интернете. Не включать публичный вызов этой версии.

Документация: https://yandex.cloud/ru/docs/functions/lang/python/context и https://yandex.cloud/ru/docs/storage/s3/s3-api-quickstart.

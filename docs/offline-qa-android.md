# Worklog Offline QA — отдельный Android-стенд

Ветка `worklog-android-offline-qa` основана на `worklog-yandex-test`.
Пакет `com.worklog.app.yandex.offlineqa`, имя **Worklog Offline QA**.
Новая APK должна устанавливаться рядом с Worklog Yandex Test №36, Android ID которого `com.worklog.app.yandex.test`. Разные пакеты имеют отдельное локальное хранилище, Android UID и область Android Keystore.

## Ограничения

- Не менять основную ветку `main` и `worklog-yandex-test`, существующие APK №26, №28 и №36.
- Не входить в QA-приложение с реальной учётной записью, не импортировать экспорт рабочих смен, не выходить из текущего аккаунта №36.
- Использовать только отдельного синтетического employee. Предыдущий `worklog.qa.20261123@example.com` отключён и не должен включаться.
- Сборка сама по себе не создаёт employee и не изменяет YDB. Тестовый клиент обращается к тому же пилотному шлюзу, что №36, поэтому аккаунты необходимо строго разделять. **Это изоляция приложения, не отдельная облачная база.**
- Перед установкой проверить наличие подписанной APK, package ID, подпись и адрес HTTPS Gateway. Работа с реальными сменами запрещена.
- Новый синтетический employee создаётся после отдельного согласования непосредственного теста. После приёмки отключить его и проверить отзыв сессий.

## План испытания

1. Проверить GitHub Actions, Android package ID `com.worklog.app.yandex.offlineqa`, подпись APK, одобренный HTTPS API Gateway.
2. Установить QA-сборку рядом с №36, не удалять и не обновлять №36.
3. Войти под новым отдельным QA employee, сохранить вымышленную смену онлайн, включить запоминание на 30 дней.
4. Отключить интернет, перезапустить только QA-приложение и отредактировать синтетическую смену без сети.
5. Восстановить интернет, проверить отправку очереди, ревизию и содержимое через вторую QA-сессию.
6. Отключить QA employee, проверить недействительность сессий; удалить только QA-приложение после приёмки.

Пока подписанная APK не собрана и тест на телефоне не выполнен, Android офлайн-запись **не подтверждена**.
